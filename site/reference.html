Reference

Everything beyond the first ten minutes: loaders, configuration, ABI, layout and troubleshooting.

Loaders

LoaderNeedsUse it when
RRDR.asi (native) ScriptHookRDR2 + dinput8.dll Default. No .NET involved.
RRDR.Host.dll (managed) ScriptHookRDR2DotNet V2 + .NET Framework 4.8 You already run ScriptHookRDR2DotNet mods.

Both scan scripts/Rscripts/ and load every DLL that exports rd_abi_version. Run only one loader: two loaders tick every mod twice per frame.

How the native loader fits

RDR2.exe
├─ dinput8.dll (ASI loader)
│  └─ RRDR.asi                    native loader
│     ├─ RRDR.asi.ini
│     └─ scripts/Rscripts/*.dll   every core exporting rd_abi_version
│
└─ ScriptHookRDR2.dll
   └─ ScriptHookRDR2DotNet.asi
      └─ scripts/Rscripts/RRDR.Host.dll   alternative managed loader
         └─ scripts/Rscripts/*.dll         same cores

RRDR.asi resolves its ScriptHookRDR2 imports at runtime with GetProcAddress and calls scriptRegister, scriptWait and nativeCall directly, so a Rust cdylib needs no .NET metadata.

Manual install

Native loader

Copy to the folder containing RDR2.exe:

RRDR.asi
RRDR.asi.ini

Then from the package's scripts/ into <RDR2>/scripts/:

Rscripts/RealisticDamagesCore.dll
Rscripts/RealisticDamages.ini

RRDR.Host.dll and RRDR.Host.ini are not needed in this mode.

Managed loader

Copy the package's scripts/Rscripts/ into <RDR2>/scripts/ and do not copy RRDR.asi.

The core ABI

A core is a Rust cdylib exporting:

  • rd_abi_version
  • rd_init_v3 (or rd_init)
  • rd_tick, rd_reload_config, rd_shutdown

The loader passes a host table with a call_native(hash, args) callback; every native call goes through the game's script thread. The full C ABI is in docs/ABI.md.

A core reads its config from <DllName>.ini next to the DLL. An empty path is passed when the file is absent.

Crate conventions

  • Do not name a mod crate rrdr-*; the prefix is reserved for the framework.
  • Do not name the DLL RRDR.* or ScriptHook*; the loaders skip those names.
  • Prefer one crate per feature so a broken mod cannot take the others down.

Generated native bindings

rrdr-natives has a typed function for every native in lib/NativeDecl.cs: 7501 functions across 86 modules.

use rrdr_natives::{entity, player};

let player_id = player::PLAYER_ID(api);
let ped = player::GET_PLAYER_PED(api, player_id);
let health = entity::GET_ENTITY_HEALTH(api, ped);
let pos = entity::GET_ENTITY_COORDS(api, ped, true, true);

Vector3 overloads use the _VEC3 suffix; every function also has a HASH_<NAME> constant for raw GameApi calls. Two variadic natives are listed in rrdr_natives::SKIPPED_VARIADIC because the ABI cannot express them.

Every generated function is documented in its own rustdoc comment: what the native does, one line per parameter (marked in or out) and the notes that came with it. Descriptions come from lib/NativeDecl.cs, then from the RDR3 native database, then from a sentence built out of the native name, so none is left empty. Parameters are named the way the declaration file names them; a bare p0, p1 takes the name the database gives it (ped, durationMs) or a name derived from its type (handle, outVec).

The merge is built once and checked in as tools/native_docs.json:

python3 tools/fetch_native_docs.py      # refresh tools/rdr3_natives.json from the database
python3 tools/generate_native_docs.py   # rebuild tools/native_docs.json (--check in CI)
python3 tools/generate_natives.py       # rewrite rust/crates/rrdr-natives/src
python3 tools/generate_natives_site.py  # rewrite site/natives

Calling natives by hand

let health = api.call_i32(GET_ENTITY_HEALTH, &[Arg::I32(ped)]);
let pos = api.call_vec3(GET_ENTITY_COORDS, &[Arg::I32(ped), Arg::Bool(true), Arg::Bool(true)]);
let mut bone = 0i32;
let valid = api.call_bool(
    GET_PED_LAST_DAMAGE_BONE,
    &[Arg::I32(ped), Arg::Ptr(std::ptr::addr_of_mut!(bone) as u64)],
);

Arguments are I32, U32, F32, Bool, U64, Str and Ptr. A Ptr points at an output variable written synchronously by the native.

Threading rules

Never call GameApi from a Rust thread: natives must run on the game's script thread. Do all work in tick, init, reload or shutdown, and keep ticks short.

Linux and Wine

The managed loader needs a real .NET Framework 4.8 install. winetricks dotnet48 can fail on Wine 11; a Wine 8/9 prefix such as wine-ge-8-26-x86_64 works. The native loader needs no .NET.

Lutris rewrites WINEDLLOVERRIDES for DXVK, so put overrides in wine.overrides instead of system.env:

wine:
  overrides:
    dinput8: n,b
    version: n,b
    ScriptHookRDR2: n,b
    ScriptHookRDRDotNet: n,b

If RDR2.exe exits right after Launcher.exe starts it, add the RDR2.exe application overrides amd_ags_x64 = builtin,native and vulkan-1 = native,builtin.

Limitations

  • x64 only.
  • Vector2, Matrix and other struct returns need an ABI extension. 64-bit, Vector3 and string returns are covered.
  • Keyboard events are not exposed by the ABI; poll control natives in tick.
  • Pool enumeration needs ABI v3, which both loaders provide.
  • The ASI loader always writes RRDR.asi.log; its log_file key is not read yet.
  • RealisticDamages is intentionally small. GET_PED_LAST_DAMAGE_BONE can be stale after a fall or fire.
